# Research Log

**Purpose.** An append-only chronological record of research activity
across this entire knowledge base — not a single author's journal.
Entries from other concurrent contributors (working on `knowledge/`,
`design-systems/`, `references/`, etc. at the same time as this batch)
may be merged in below by date as their work lands. Do not reorder or
edit past entries to "clean up" the log — append new ones, and if a
later finding revises or contradicts an earlier entry, add a new entry
that says so and references the old one, rather than rewriting history.

## How to add an entry

Use exactly this row format (one row per entry, pipe-delimited):

```
DATE | SOURCE | TOPIC | KEY FINDINGS | FILE(S) UPDATED | CONFIDENCE | POTENTIAL IMPACT
```

- **DATE** — ISO format, the date the research/writing happened.
- **SOURCE** — where the finding came from (a specific search, a named
  reference, "own synthesis/reasoning" if no external source was
  consulted, a specific article/doc if one was).
- **TOPIC** — short phrase, what this entry is about.
- **KEY FINDINGS** — one to three sentences, the actual substance.
- **FILE(S) UPDATED** — path(s) this research produced or changed.
- **CONFIDENCE** — one of: FOUNDATIONAL, ESTABLISHED, CONTEXTUAL,
  EMERGING, EXPERIMENTAL, VISUAL TREND (see
  `knowledge/ui-principles-2026.md` for the taxonomy).
- **POTENTIAL IMPACT** — what else in the knowledge base this might
  affect or should be cross-checked against, if anything.

Keep each entry to roughly one line where possible; use a short
sub-list under KEY FINDINGS only if genuinely needed. New entries go at
the bottom of the table, in date order as they're written (not
alphabetical, not by topic).
